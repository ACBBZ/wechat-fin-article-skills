# 专业分析稿与 Style Skill 交接

本文件服务第 2 步专业分析稿和第 5–6 步事实锁定 / 文风交接。核心原则：**Writer 先把事实和逻辑做对，再由 `fin-writing-style` 把表达做成人能一路读下去的 3000–3600 字长文。**

## 第 2 步：专业分析稿

这一阶段不追求最终公众号文风，目标是把后续不可丢失的信息写完整。

必须包含：

- 当前事件和直接事实；
- 数据口径；
- 至少一层关键机制；
- 反面证据或替代解释；
- 历史材料的可比与不可比；
- 核心问题；
- 暂定判断；
- 判断成立条件和不确定性。

### 结构

不再要求恰好两个 `##` 小标题。专业分析稿可以按研究需要临时分段，但这些标题不构成最终正文契约。

### 一句一段

最终发布稿仍要求每个完整句子单独成段并留一个空行。专业分析阶段可提前遵守，方便后续 Style Skill 保持移动端节奏。

### 数据

每个数据必须服务于一个判断；同一段不要堆超过 3 个相互独立的数据点。不同口径不得混写成同一序列。

## 第 5 步：事实锁定

事实核查完成后，把不能被文风改变的内容显式写进 `style_context`。

至少包括：

```yaml
verified_facts: []
locked_numbers: []
locked_quotes: []
counter_evidence: []
historical_context: []
uncertainty_constraints: []
author_experience: []
author_opinions: []
```

### `locked_numbers`

保存正文要使用的重要数字和口径。Style Skill 可以调整句序，但不能把 17.3% 写成“接近 20%”，也不能为了口语化改时间区间、币种或单位。

### `locked_quotes`

保存经过核验、允许进入正文的引语。Style Skill 不得自行扩写、省略到改变原意或把转述包装成直接引语。

### `uncertainty_constraints`

明确哪些结论只能写成“可能、仍需观察、目前没有证据证明”等强度。Style Skill 不得把这些限定删掉。

### `author_experience`

只有用户明确提供的真实经历才记录。没有就保持空数组，不得为了第一人称作者感自行补经历。

## 第 6 步：调用 `fin-writing-style`

Writer 把专业分析稿和完整 `style_context` 交给 Style Skill，目标正文为 3000–3600 可见字，推荐 3200–3400。

默认：

- `article_type: research_analysis`；
- `first_person: true`；
- `tone_intensity: natural`；
- 不要求 `##` 小标题；
- 返回语义 `section_anchors` 给正文配图使用。

## Style 返回后的事实对照

逐项比较第 5 步版本和 Style 版本：

- 数字、单位、日期是否一致；
- 引语是否一致；
- 不确定性是否保留；
- 反面证据是否还在；
- 是否新增事实、人物关系或因果；
- 是否把历史类比写得更确定；
- 是否出现输入中不存在的第一手经历；
- 核心判断的强弱是否变化。

任何事实变化都按事实锁修正，而不是把它当成“文风优化”。

## 最终排版

Style 完成后，最终正文继续遵守：

- 每个完整句子后两个换行符；
- 图片和图注独立成块；
- 信息来源区保持 `- 机构：《标题》，日期。`；
- 来源条目之间留一个空白行。

正文的口语风格规则不得破坏来源、图注或机器字段格式。
