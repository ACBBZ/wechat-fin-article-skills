# 公众号财经内容合规与图片权利指南

本指南把上传的《公众号内容合规指南》扩展为可执行规则。核心原则仍然是：**事实可验证、观点有依据、表述够谨慎。** 本文件不是法律意见；平台规则或法律要求变化时，应以最新可核验规则为准。

## 使用方式

第 1 步研究、第 5 步事实核查、第 8 步配图和第 10 步交付前都要读取本指南。遇到高风险事实时，不要靠“语气变软”解决证据不足；先补证据，补不到就删或明确不确定。

## 平台与内容红线

### 虚假信息、谣言

**规则说明：** 不得把未经证实的传言、匿名消息、二手截图写成事实。财经文章尤其容易因为“市场传闻”影响公司和证券价格，因此证据门槛要高。

**执行动作：**

1. 追溯最初出处；
2. 检查是否有公司公告、交易所公告、监管文件或可靠媒体独立核验；
3. 只能找到传言时，不作为核心事实；确有新闻价值时明确写“截至发稿时未获官方确认”。

**处理示例：**

- 不合格：“某公司即将被收购，股价可能起飞。”
- 合格：“社交平台出现收购传言，但截至发稿时公司与交易所均未发布相关公告，本文不据此作判断。”

### 抄袭、洗稿

**规则说明：** 不能直接复制他人文章段落、标题结构或独家表达后仅做同义词替换。引用公开事实和数据可以，但表述必须重新组织并标明来源。

**执行动作：** 只摘取事实、数据和必要短引语；正文使用自己的逻辑和措辞。对媒体独家采访、深度调查等内容，提高引用克制度并保留原媒体归属。

**处理示例：** 不要复制媒体三段分析再换几个词；应回到其引用的公告、数据或原始材料，重新构建自己的论证。

### 投资建议、荐股与诱导交易

**规则说明：** 上传指南明确禁止“建议买入、目标价、强烈推荐、必涨、机构内幕消息”等表述。文章可以分析事实、估值、行业和风险，但不能直接告诉读者买卖某只证券，也不能承诺收益。

**执行动作：**

- 删除“现在上车、赶紧卖、目标价、稳赚、必涨”等交易指令；
- 对机构观点明确标注机构、时间和来源；
- 把“应该买”改成“市场目前关注的变量是……”，前提是这句话有真实材料支撑。

**处理示例：**

- 不合格：“这个位置可以大胆买入。”
- 合格：“估值较历史区间下降，但盈利修复是否持续仍取决于订单和现金流，公开信息不足以支持确定性判断。”

### 内幕信息与未公开重大事项

**规则说明：** 未公告的并购、业绩、重大合同、高管变动等敏感信息，不能因为“圈内听说”就写入。

**执行动作：** 只使用已经公开的信息；记录发布时间；涉及市场传闻时主动查公司公告和交易所问询。

**处理示例：** 不要写“我提前得知公司将发布大订单”；可以写“公司已于某日公告签署合同，合同金额和履约条件如下”。

### 炒作股价与违法广告

**规则说明：** 不能用夸大标题、收益暗示、操纵式号召推动交易，也不能把软文包装成独立分析。

**执行动作：** 删除煽动性买卖号召；如存在商业合作或利益关系，按适用规则显著披露，不把广告内容伪装成客观研究。

## 需谨慎处理的内容

### 上市公司负面信息

**规则说明：** 涉及造假、违规、经营恶化、管理层争议等内容，必须有可靠来源，区分“监管认定”“媒体调查”“市场质疑”“作者推断”。

**执行动作：** 优先监管决定、公司公告、法院文书、交易所文件；媒体报道作为补充。标题不能把“被问询”写成“已违法”。

### 行业争议

**规则说明：** 上传指南要求呈现多方观点。这里的“多方”必须来自真实可核验材料，不能为了形式平衡而虚构一个反方。

**执行动作：** 搜索支持与反对证据；如果公开资料只有一方，明确写“暂未找到可靠公开反方材料”，而不是编造“业内人士认为”。

### 政策解读

**规则说明：** 必须以官方原文为底座，准确区分“正式实施、征求意见、拟修订、试点、指导意见”等状态。

**执行动作：** 先引用官方文件，再看权威媒体解释；标题、正文和封面都保留政策状态。

**处理示例：**

- 不合格：“LOF 退出新规已经落地。”
- 合格：“交易所就 LOF 退出安排征求意见，最终规则仍以正式发布文件为准。”

### 人物报道与名誉风险

**规则说明：** 评价个人动机、能力、道德和违法行为时，要区分事实与观点。未经确认的负面指控不得写成确定事实。

**执行动作：** 使用公开履历、正式采访、公告、监管或司法文件；删除没有来源的心理揣测。

## 数据引用规范

### 规则说明

上传指南要求财务数据、市场数据和研究结论标明来源。新版进一步要求记录时间和口径。

### 执行动作

- 财务数据：优先公司财报、公告、交易所披露；Wind、Choice、同花顺 iFinD 可用于交叉核对。
- 市场数据：优先交易所、指数公司、基金公司和权威数据平台。
- 宏观数据：优先国家统计局、中国人民银行、财政部、海关等官方机构。
- 研究结论：写明券商或研究机构名称、报告日期，不能只写“机构认为”。
- 同一指标出现冲突时先查统计口径，再决定使用哪一个。

**处理示例：**

不推荐“根据数据显示”；应写“国家统计局公布的某月数据为……”“公司年报显示……”“中金公司某日研报认为……”。

> 上传原指南把“值得关注的是”列为合规表述；合规层面它并非禁语，但本 Skill 的表达规则把这类空洞提示词视为高风险 AI 元话语。没有必要时应直接写后面的事实或判断。

## 争议性内容与不确定性

### 规则说明

当证据无法支持唯一结论时，必须让读者知道不确定性来自哪里，而不是用模糊语气掩盖。

### 执行动作

- 明确不同观点对应的机构或来源；
- 使用“截至发稿时”“就目前公开信息”“仍需观察”等时间边界时，要说明具体缺口；
- “可能、或许”不能成为无证据猜测的通行证，仍需方向性证据。

**处理示例：**

不合格：“市场普遍认为政策利好。”

合格：“证券时报和财联社报道中，多家受访机构认为该规则可能改善退出效率；但正式实施细则尚未公布，实际影响仍取决于适用范围。”

## 文字版权合规

### 规则说明

公开事实可以引用，独特表达、深度分析、采访内容和原创图表不能直接搬运。

### 执行动作

- 长段材料改为摘要，并保留来源；
- 必要直接引语只保留最关键部分；
- 不“洗稿”，不通过同义替换规避版权；
- 媒体独家内容只作为来源之一，能回到原始文件时优先回原始文件。

## 图片合规

### 基本原则

“网上搜得到”不等于“可以转载”。公开可访问与拥有发布权是两件事。图片必须同时检查事实匹配和使用权利。

### 可自动插入的图片

`AUTO_INSERT` 仅用于：

- 使用条件明确、可追溯的官方公开材料；
- 用户明确拥有使用权的图片；
- 开放许可或公共领域图片；
- Agent 基于已核实数据自行生成的原创数据图、机制图、时间线图。

所有最终正文图片统一输出为 PNG。

### 仅保留候选的图片

`CANDIDATE_ONLY` 包括：新闻媒体摄影记者作品、商业图库、带版权标识但无转载许可的图片、无法确认许可范围的现场图。这类图可记录来源给用户人工确认，但不能自动插进发布稿。

### 必须拒绝的图片

`REJECT` 包括：来源不明、时间不明、二手搬运、水印被抹除、与事件不匹配、AI 图冒充真实新闻现场、只有搜索缩略图没有原网页。

### 禁止“洗图”

不得通过裁掉水印、镜像、改色、重绘媒体摄影图等方式规避权利。格式转换为 PNG 只改变文件容器，不改变版权状态。

### 新闻图事实匹配

每张真实新闻图片至少核对：事件、日期、主体、来源、图注。正文讲 2021 年事件，就不能拿 2023 年相似事件的图片冒充。

### 至少两张配图的合规补足

如果权利清楚的真实新闻图不足两张，必须用已核实事实或数据制作原创 PNG 图补足，不得为了数量要求降低版权标准。最终至少两张 `AUTO_INSERT` 配图分别放在两个 `##` 小标题之前。

## 发布前检查

发布前逐项确认：

- [ ] 所有核心事实是否能追溯到具体来源？
- [ ] 最新政策、职位、行情和数据是否用当前资料核实？
- [ ] 是否存在具体买卖建议、收益承诺或目标价？
- [ ] 是否存在未经确认的传言或内幕暗示？
- [ ] 因果、外推和历史类比是否超出证据？
- [ ] 上市公司负面信息是否达到更高证据门槛？
- [ ] 争议问题是否真实搜索过反面证据？
- [ ] 引用是否标明来源，是否存在复制或洗稿风险？
- [ ] 正文是否至少 2 张 PNG 配图？
- [ ] 两张必需配图是否分别紧邻两个 `##` 小标题之前？
- [ ] 每张自动插图是否有原始来源、图注、事件匹配和 `AUTO_INSERT` 状态？
- [ ] 是否误把“公开可访问”当成“可以转载”？
- [ ] 封面是否把“拟议、可能、历史事件”画成确定事实？

## 常见违规警示

| 风险类型 | 典型表现 | 正确处理 |
|---|---|---|
| 荐股 | “明天买入必涨” | 删除交易指令和收益承诺，改为事实与风险分析 |
| 传播谣言 | “某公司暴雷传闻”但无确认 | 追原始来源；无法确认则不作为事实 |
| 抄袭洗稿 | 大段复制他人文章 | 回到原始材料，原创组织和表达 |
| 内幕信息 | “提前得知并购消息” | 只使用已公开公告 |
| 图片侵权 | 搜索到媒体摄影图直接转载 | 仅保留候选，改用有权图片或原创图 |
| 事实误导图 | 用别的年份相似事件配当前段落 | 核对事件、日期、主体，不匹配则不用 |

**最终原则：真实性优先于速度，证据优先于情绪，权利优先于图片数量。**

## 高风险场景的具体处理流程

### 场景一：上市公司“暴雷”或重大负面新闻

遇到“财务造假、重大亏损、实控人出事、债务违约、被立案”等选题时，按下面顺序处理：

1. **确认事件性质**：先找公司公告、交易所公告、证监会或其他监管文件，确认究竟是“传闻、问询、立案、处罚、判决”中的哪一种；
2. **确认时间**：同一家公司可能经历“被媒体质疑 → 交易所问询 → 证监会立案 → 行政处罚”多个阶段，不能把后面的结论倒灌到前面的时间点；
3. **区分事实与评价**：监管决定可以作为事实；“管理层故意”“公司已经资不抵债”等判断需要额外证据；
4. **核对标题**：标题不能把“被立案调查”写成“已被认定造假”，不能把“业绩预亏”写成“已经破产”；
5. **配图检查**：优先公司公告、监管文件截图或官方公开资料。媒体摄影若权利不清，只做候选。

**处理示例：**

- 原始材料只有“证监会决定对公司立案”，正文就写“被立案调查”，不要写“造假被坐实”。
- 如果后续已有正式处罚决定，可以在历史部分说明“立案后于某日被处罚”，但要明确时间顺序。

### 场景二：政策征求意见或拟修订

政策类文章最容易把状态写重。执行时至少检查：

- 文件标题里是否有“征求意见、草案、试行、暂行、通知、决定”等效力提示；
- 正文是否写清“当前状态”；
- 是否有正式生效日期；
- 媒体报道是否把专家推测误当作官方目的；
- 封面是否把“拟”画成“已经执行”。

**处理示例：**

“交易所就某规则征求意见”可以写“拟完善”，不能写“已经全面实施”。如果正式稿后来发布，必须用最新文件重新核验，不沿用旧稿条文。

### 场景三：市场大涨大跌与原因归因

价格变化是事实，原因通常不是单一事实。处理顺序：

1. 先确认行情数据、时间区间和幅度；
2. 找公开可确认的直接触发信息，例如公告、政策、财报；
3. 对“资金博弈、情绪、预期”等归因标注为可能因素，并给来源；
4. 不用“一定因为、完全由于”解释复杂市场波动，除非有非常强的证据。

**处理示例：**

可以写“公告发布后股价下跌 8%，市场报道将业绩低于预期视为主要触发因素”；不要仅凭同日发生就写“股价下跌就是因为管理层失去信任”。

### 场景四：基金溢价、LOF、ETF 等场内异常

- 先区分基金净值、场内交易价格、估值和申赎机制；
- 溢价率必须核对计算口径和对应日期；
- 历史高溢价可以解释机制风险，但不能自动证明今天的规则调整就是针对该次事件；
- 风险提示公告、停牌、限购等措施要找基金公司或交易所原文；
- 配图优先使用官方风险提示、经核实的价格/净值数据图；若媒体行情截图权利不清，自己用核实数据画 PNG。

### 场景五：传言已经引发市场反应

即使传言“确实导致了市场讨论”，传言本身仍不等于事实。文章可以写：

> 某传言在市场传播后，相关资产出现波动；截至发稿时，尚未找到官方材料确认传言内容。

这里可以把“传言的传播存在”作为事实，但不能把“传言内容为真”写成事实。

## 引语与采访内容的具体规则

- 直接引语必须能找到原始采访、发布会、公告或可靠报道；
- 如果无法核对原句，改为间接引语并写明来源；
- 不把一句话截掉条件后变成更强结论；
- 对媒体独家采访，尽量摘要而非大段复制；
- “市场人士称”“知情人士称”只有在来源媒体本身可靠、且文章明确保留匿名属性时才能谨慎使用，不能自行升级为已确认事实。

## 图表生成的合规要求

Agent 自行制作数据图时，也需要遵守事实完整性：

1. 数据必须来自文章已经核验的来源；
2. 标明数据期、单位和来源；
3. 不截取极端时间窗口制造视觉冲击；
4. 不通过不合理坐标轴放大差异；
5. 两组数据口径不一致时不能强行放在一张图比较；
6. 生成后的图保存为 PNG，并在图注写“数据来源：……；本账号整理/绘制”。

## 图片权利判断的执行表

| 问题 | 是 | 否 |
|---|---|---|
| 能否找到原始页面或原始文件？ | 继续 | `REJECT` |
| 图片是否确实对应正文事件和日期？ | 继续 | `REJECT` |
| 是否明确属于用户自有、开放许可、公共领域、可用官方材料或原创图？ | `AUTO_INSERT` 候选 | 继续判断 |
| 是否为媒体摄影、商业图库或许可不明确图片？ | `CANDIDATE_ONLY` | 继续判断 |
| 是否存在抹水印、来源不明、二传截图？ | `REJECT` | 继续 |
| 自动发布权利仍不明确？ | `CANDIDATE_ONLY` | 按已确认条件处理 |

## 最终发布记录建议

为了以后追溯，`article-package.json` 中建议为每个高风险事实和图片保留：

- 来源名称；
- 原始页面 URL；
- 发布时间；
- 核验时间；
- 证据层级；
- 支撑哪一条正文事实；
- 图片权利状态；
- 是否自动插入；
- 如果删除或降级，记录原因。

这样做的目的不是制造审核日志负担，而是在文章发生争议时能够回答“这句话和这张图当时依据什么公开材料”。
