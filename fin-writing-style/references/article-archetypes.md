# 六种文章原型

写之前先选一个主原型。可以混合，但只能有一个主要推进逻辑。

## 调查实验型

适合作者确实亲自做过一件事并有可验证过程素材。

主线：具体好奇 → 下场 → 遇到问题 → 继续试 → 层层发现 → 新理解。

硬条件：`author_experience` 必须包含真实行动。没有真实经历就不能把普通研究稿伪装成调查实验。

## 产品体验型

适合有真实使用记录、截图、操作步骤和明确感受的产品体验。

主线：为什么试 → 进入具体场景 → 逐一展示 → 好坏判断 → 适合谁/不适合谁。

不要写成参数表。读者应该感觉自己跟着作者一起用了一遍。

## 现象解读型

适合市场现象、社交热点、用户行为和反常数据。

主线：观察 → 好奇 → 表面解释 → 新事实 → 更深追问 → 机制 → 更大的参照 → 判断。

核心不是“告诉读者答案”，而是让读者跟着完成一次思考。

## 工具分享型

适合工具、Prompt、流程或工作流推荐。

主线：真实问题 → 为什么原方法不够 → 工具出现 → 具体用法 → 效果 → 局限和学习成本。

没有真实体验时，不得编造“我用了之后”的故事，可以坦白写“我还没有完整跑通”。

## 方法论分享型

适合经验总结、教程和 N 条心得。

每一节都要给读者一个能执行的动作，同时说明成本、失败点或不适用条件。允许数字编号或可见分段结构，但不要写成论文式章节。

姿态要谦逊：分享自己当前有效的方法，不假装它是普适真理。

## 研究判断型

财经、公司、政策、行业和市场深度稿的默认原型。

推荐推进：

1. 一个反常事实、数字或冲突；
2. 我为什么觉得这里值得多看一眼；
3. 把当前事件讲清楚；
4. 第一层机制解释；
5. 放入反面证据或替代解释；
6. 再往下一层追问；
7. 连接历史、行业或文化参照，但交代不可比处；
8. 给出第一人称判断；
9. 明确判断成立条件和可能失灵的情形；
10. 回到开头的意象或问题完成 callback。

研究判断型不依赖真实亲历，也不应该虚构现场感。作者感主要来自“注意点、推理选择、判断和边界”。
