# 第一人称真实性边界

第一人称的目标不是让每一段都出现“我觉得”，而是让读者知道：这篇文章背后有一个人在选择注意什么、如何理解证据、在哪里保留怀疑。

## 三层第一人称

### 观察型

任何有明确素材输入的文章都可以使用。

可用：

- 我第一眼更关心的是……
- 我看到这组数据时，先去看了……
- 我真正想追的是另一个问题。

这里的“看”必须对应输入中确实存在的材料，不得暗示参加过现场或获得过非公开材料。

### 判断型

财经文章的主要作者感来源。

可用：

- 我的判断反而没那么乐观。
- 我更倾向于第二种解释。
- 我现在还不愿意把它叫作趋势。
- 这件事我觉得最容易被低估的是……

判断必须保留证据强度。“我认为”不能把相关性变成因果，也不能把可能变成确定。

### 经历型

只有 `author_experience` 明确提供时可用。

可用输入示例：

```yaml
author_experience:
  - "2026年8月实际购买并使用了这个产品"
  - "参加了这场公开发布会，并记录了现场演示"
```

只有这种情况下才可以写“我买回来试了一遍”“我在现场看到”。

## 绝对禁止

在没有明确素材时，不得自行写：

- 我身边很多基金经理都……
- 我跟业内朋友聊了聊……
- 我当时就在现场……
- 我自己买过这只股票……
- 我过去几年一直在这个行业……
- 我父亲/朋友/同事曾经……

这些句子即使“听起来更真人”，本质上仍是编造。

## 作者观点输入

`author_opinions` 可以允许更强的个人表达，但仍不能改变事实。例如：

```yaml
author_opinions:
  - "我认为市场过度关注短期利润，低估了现金流质量"
```

可以扩写为判断与推理，但不能把它包装成已经被数据证明的事实。

## 第一人称密度

3000–3600 字长文通常不需要高频重复“我”。建议在以下位置出现：

- 开篇注意点；
- 一到两个关键转折；
- 核心判断；
- 判断边界；
- 结尾 callback。

其余段落让事实、案例和机制自己说话。作者感来自选择与节奏，不来自代词数量。

## 谦逊不是模板

允许“我也不完全确定”“这个判断可能会错”，前提是确实存在不确定性。不要为了显得真诚机械插入自谦。
